# Stages

The high-level plan: what each stage is for, when it counts as done, and what it must not touch. Work-by-work detail goes in [progress.md](progress.md); the design itself is in [architecture.md](architecture.md).

**Current design:** architecture v2.0, checkpoint **v2.5** · **Current stage:** 2 (in progress: waiting on the API key and the gold review)

| # | Stage | Status |
|---|---|---|
| 1 | Spec, KB outline, environment check | done 2026-11-12 |
| 2 | Knowledge-base data, data checks, gold set | **in progress** |
| 3 | Notebook 1: retrieval without an LLM | not started |
| 4 | Notebook 2: LLM-built graph and grounded answers | not started |
| 5 | Extras: geo, shortest-path explanations, text-to-AQL, comparison with ArangoDB's GraphRAG tooling | planned, not scheduled |
| 6 | Publish: final README, fresh-clone test, spec to reviewers | not started |

Rule for every stage: when it ends, run the checks in [eval.md](eval.md). If a score drops and no change was meant to cause it, stop and wait for Tianyi.

---

## Stage 1: spec, KB outline, environment check (done 2026-11-12)
**Goal:** agree on what is being built, before building it.
**Done when:**
- [x] `docs/SPEC.md`: problem, idea, what a developer learns, evaluation, rules
- [x] `docs/KB_OUTLINE.md`: every article, form, state, lender, lessor; versions; tricky cases
- [x] `scripts/verify_env.py` passes: vector index, filtered vector search, BM25, form-code tokens
- [x] seed questions: 16 candidates, all kept by Tianyi (2026-11-13)

**Out of scope:** writing article text; any retrieval code.

## Stage 2: knowledge-base data, data checks, gold set (in progress)
**Goal:** all the data the cookbook runs on exists, matches `docs/KB_OUTLINE.md`, and a script checks it.
**Done when:**
- [x] 51 articles / 68 versions in `data/kb/articles/*.json`, with `kb:` links and `NW-` form codes in the text
- [x] `forms` (15), `states` (5), `lenders` (12), `lessors` (6), `stores` (25)
- [x] the six "facts the articles must state" from `data/eval/seed_candidates.md` are in the articles
- [x] the KB problems left in on purpose are present and listed as known issues in the data
- [x] `make check` passes
- [x] `data/eval/gold.json`: 56 questions, 8 per type (16 seeds kept by Tianyi + 40 drafts)
- [ ] Tianyi has reviewed the 40 drafts, and the gold set is frozen (commit + sha256)
- [ ] about 200 tickets generated by `scripts/generate_tickets.py`, cached and committed, and covered by `make check` (plan and dry run done; generation needs the API key)

**Out of scope:** loading into ArangoDB, embeddings, retrieval, notebooks. Changing the outline's structure is an architecture change: ask first.
**Waiting on Tianyi:** an API key in `.env` (for tickets); review of the 40 draft questions.

## Stage 3: notebook 1, retrieval without an LLM
**Goal:** a developer runs one notebook and sees each ArangoDB retrieval feature, then the scores.
**Done when:**
- [ ] `notebooks/01_search_vectors_and_the_kb_graph.ipynb` runs top to bottom in under 2 minutes on a laptop CPU, with no API key
- [ ] methods M1–M5 (see architecture), each a single AQL query printed in the notebook
- [ ] eval table by question type × method, including the BM25 vs vector baseline at Recall@10
- [ ] scores saved to `data/eval/scores/latest.json`

**Out of scope:** LLM calls; changes to the frozen gold set.

## Stage 4: notebook 2, LLM-built graph and grounded answers
**Goal:** show what an LLM adds on top of the structural graph, and measure it.
**Done when:**
- [ ] entity and relation extraction (structured outputs), cached as JSON and committed
- [ ] extraction scored against a hand-labelled sample (precision and recall)
- [ ] M6 (semantic-graph expansion) and M7 (checklist traversal)
- [ ] grounded answers with citations; answer eval (required facts, valid citations, refusals, trap-caused errors)

**Out of scope:** changing chapter 1 methods or the gold set.

## Stage 5: extras (planned, not scheduled)
Geo (nearest store with a given service, `GEO_DISTANCE` plus the graph in one query), `SHORTEST_PATH` as an explanation ("why do I need this form?"), text-to-AQL, and a comparison with ArangoDB's own GraphRAG tooling and `langchain-arangodb`.

## Stage 6: publish
**Done when:**
- [ ] Tianyi has rewritten the README, SPEC and notebook prose in his own words
- [ ] a fresh clone in a new folder works by copy-pasting the README commands
- [ ] a one-page spec is sent to the reviewers
